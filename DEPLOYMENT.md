# Deployment Guide

This guide covers production configuration, validation, Docker deployment,
health checks, secret handling, and rollback for EbookGuy Filtering Bot.

## Production Requirements

- Telegram API application ID and hash
- A Telegram bot token
- MongoDB reachable from the deployment environment
- At least one administrator Telegram user ID
- A platform capable of running the Docker image or Python 3.10
- Calibre when ebook conversion is enabled

## Required Environment Variables

| Variable | Example format | Description |
| --- | --- | --- |
| `API_ID` | `123456` | Integer Telegram API application ID |
| `API_HASH` | `replace_me` | Telegram API application hash |
| `BOT_TOKEN` | `replace_me` | Bot token generated by BotFather |
| `DATABASE_URI` | `mongodb+srv://...` | Primary MongoDB connection string |
| `ADMINS` | `123456789 987654321` | Space-separated administrator IDs |

The bot exits during startup with a list of missing required variables. `API_ID`
must be an integer, and `ADMINS` should contain numeric Telegram user IDs.

When `MULTIPLE_DATABASE=true`, the following values are also required:

- `O_DB_URI`
- `F_DB_URI`
- `S_DB_URI`

Start from `.env.example` for the complete optional configuration.

## Secret Handling

- Store production secrets in the hosting platform's secret manager.
- Use `.env` only for local development.
- Never commit `.env`, bot tokens, database credentials, or `.session` files.
- Do not place secrets in Docker build arguments or image layers.
- Rotate credentials immediately if they appear in Git history or logs.

The bot uses an in-memory Pyrogram session. A local `EbookGuyBot.session` file
should not be created during normal startup.

## Credential Remediation Before Deployment

An older `EbookGuyBot.session` file was committed in previous public revisions.
Complete these actions before using the repository for the main production bot:

1. Revoke the exposed token through BotFather.
2. Generate a replacement token.
3. Replace `BOT_TOKEN` in local and hosted secret stores.
4. Remove `EbookGuyBot.session` from every published Git revision.
5. Invalidate old clones or notify collaborators to re-clone after the history
   rewrite.
6. Confirm that the public repository no longer exposes the file.

Rewriting published history changes commit IDs and affects every collaborator.
The repository owner should coordinate that operation. A safer alternative for
a small project is to create a clean replacement repository from the sanitized
current tree and archive the compromised repository.

Deleting the file from the latest commit does not remove it from older commits.

## Local Production Check

Create an isolated environment and install the locked dependencies:

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --requirement requirements.lock
Copy-Item .env.example .env
```

Set real local values in `.env`, then run:

```powershell
python bot.py
```

Verify:

```powershell
Invoke-RestMethod http://127.0.0.1:8080/health
Invoke-RestMethod http://127.0.0.1:8080/ready
```

Expected responses:

```json
{"status": "ok"}
```

```json
{"status": "ready"}
```

`/health` can succeed while the bot is still initializing. Route production
traffic only after `/ready` returns HTTP `200`.

## Docker

Build the image:

```bash
docker build --tag filtering-bot .
```

Run it:

```bash
docker run --detach \
  --name filtering-bot \
  --publish 8080:8080 \
  --env-file .env \
  --restart unless-stopped \
  filtering-bot
```

Inspect its status:

```bash
docker ps
docker logs --follow filtering-bot
docker inspect --format '{{json .State.Health}}' filtering-bot
```

The Docker image:

- Uses Python 3.10
- Installs dependencies from `requirements.lock`
- Installs Calibre
- Runs as a non-root user
- Excludes local credentials, sessions, logs, caches, and agent files
- Checks `/ready` every 30 seconds

## Heroku-Compatible Deployment

`heroku.yml` uses the repository `Dockerfile`, and `Procfile` starts
`python bot.py`.

Configure all required environment values as platform config variables. Do not
upload `.env`.

The platform must route its assigned `PORT` to the process. The bot reads
`PORT` automatically and binds the health server to all container interfaces.

## Health and Shutdown

| Endpoint | Success | Failure meaning |
| --- | --- | --- |
| `/health` | Process event loop is serving HTTP | Process is stopped or unreachable |
| `/ready` | Telegram client and startup state are initialized | Service is still starting or shutting down |

During shutdown, the process:

1. Marks itself unready.
2. Cancels background refresh and notification tasks.
3. Stops the HTTP runner.
4. Stops Telegram clients.
5. Clears in-memory client state.

Allow the platform enough termination grace time for this sequence.

## Continuous Integration

`.github/workflows/ci.yml` runs on pushes and pull requests targeting `main`.

The quality job:

- Installs `requirements.lock` on Python 3.10
- Runs `pip check`
- Audits dependencies with `pip-audit`
- Rejects tracked `.env` and `.session` files
- Rejects Telegram token and credential-bearing MongoDB URI patterns
- Compiles Python sources
- Runs the regression test suite

The container job builds the production Docker image after the quality job
passes.

Do not deploy a revision with failing CI.

## Pre-Deployment Checklist

- [ ] Telegram bot token has been rotated
- [ ] Historical session file has been purged or the repository replaced
- [ ] Required environment variables are configured
- [ ] `ADMINS` contains the correct Telegram user IDs
- [ ] MongoDB permits connections from the deployment environment
- [ ] Telegram channel IDs are correct
- [ ] Bot is an administrator in configured channels where required
- [ ] `/settings` values have been reviewed
- [ ] Telegram Stars prices have been reviewed
- [ ] External payment portal is HTTPS or left unset
- [ ] Tests and dependency audit pass
- [ ] Docker image builds
- [ ] `/ready` returns HTTP `200`
- [ ] `/start`, search, download, request, `/plan`, and `/settings` are tested

## Rollback

Keep the previous known-good image tag. If a deployment fails:

1. Stop routing traffic to the new revision.
2. Restore the previous image without changing the database.
3. Review startup and application logs.
4. Confirm `/ready` on the restored revision.

Do not roll back to a revision that contains exposed credentials or persistent
Telegram session files.

## Troubleshooting

### Missing required environment variables

The startup error names every missing required variable. Configure them in the
same environment that launches `python bot.py`.

### Readiness remains at HTTP 503

Check Telegram authentication, MongoDB connectivity, and startup logs. The
service does not become ready until required startup initialization completes.

### Channel restart notification fails

Confirm that the bot is an administrator in the configured log and file
channels. Subscription-only channels are not restart-notification targets.

### Conversion fails

Confirm that `ebook-convert` is installed and available on `PATH`. Docker
installs Calibre automatically.

### External payment button is missing

Set `PAYMENT_WEBSITE` to a complete `https://` or `http://` URL. Invalid or
empty values intentionally hide the portal button.
